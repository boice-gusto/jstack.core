The two-package model

jstack.core is the generic team-operations toolkit — it ships no company-specific values and is the thing another org could adopt as-is. jstack.gusto is an overlay: org-specific skills, real internal URLs, org policy, and thin wrappers that layer on top of core skills. Anything naming a real team, channel, ticket project, or internal host belongs in the overlay, never in core.

core = generic, shippableoverlay = org-specificinstall core first

Most skill bodies are generated — read this before editing one

scripts/apply_detailed_skills.py regenerates the body of most skills/**/SKILL.md files from dicts in scripts/apply_detailed_skills_data.py. A handful of hand-maintained skills are protected by a SKIP set in that script.

If you hand-edit the body of a skill that is not in SKIP, your work is silently destroyed the next time anyone regenerates. To change a generated skill, edit the generator data — or add the skill to SKIP to take it over by hand.

Frontmatter is different: keys other than name, description, category, and when_to_use survive regeneration. Note that frontmatter must use inline scalars — allowed-tools: a, b. A YAML block list (- item) is dropped by the generator's line-based parser.

Adding a skill, end to end

1. Create skills/<category>/<name>/SKILL.md
2. Frontmatter: name, description (say when to use AND when not to), category, effort
   - write/publish skill?  add disable-model-invocation: true
   - pure read/research?   add context: fork  +  agent: Explore
   - unattended routine?   add disallowed-tools: AskUserQuestion
   - calls MCP tools?      add allowed-tools: mcp__x__y, mcp__x__z
3. Add eval cases under skills/<path>/evals/*.yaml  (coverage is gated — see below)
4. bun run agents-check      # validates frontmatter + every jstack:* token resolves
5. bun run docs:generate     # refresh the catalog
6. bun run check             # the full gate CI runs
Eval coverage is enforced: eval:quick fails if any skill lacks semantic evals. That's deliberate — a skill without evals can't be shown to still work. Override for a single run with JSTACK_EVAL_COVERAGE_MIN=90 if you must land a skill ahead of its tests.

What leaves your machine

Nothing, unless you turn it on. Telemetry is opt-in and carries skill name, token count, and latency only. MCP servers talk to whatever service you configured them for. Semantic evals call the Claude API and cost money, which is why CI runs only the free structural pass. Config files hold IDs and URLs — never tokens.

Troubleshooting

jstack doctor reports .mcp.json (optional)
Advisory, not a failure — it no longer affects the exit code. Copy .mcp.json.example only if you actually want MCP servers.
Missing jstack.config.json
Finish this wizard and save the file at your project root, or run jstack setup --schema.
bun run check fails on eval coverage
A skill has no eval cases. The error names the skills. Scaffold with bun run generate-skill-evals, then replace the scaffold with cases that would actually fail if the skill broke.
Chain validation fails
A jstack:* reference points at a skill that doesn't exist. Run bun run validate-chains and bun run agents-check; compare against the real name: values in skills/**/SKILL.md.
My skill edit disappeared
The body was regenerated. See "How this repo works" — edit the generator data or add the skill to SKIP.
A skill says an integration isn't configured
Working as intended: skills refuse to invent IDs. Add the integration to your config and re-run jstack doctor.
Semantic evals do nothing
They need ANTHROPIC_API_KEY and claude on PATH. They are not run by CI because they cost money.
Generated config stays in your browser until you save it. No network calls.
